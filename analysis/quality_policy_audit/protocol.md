# E37S / D56S: mask-dependent classifier input quality audit

Recorded 2026-10-04 after organiser feedback and E36S failure review, before running these policy comparisons. This is feedback-informed development. The first drop cannot be untouched validation of a policy developed here. Existing D52 v2 sources, fitted models, predictions and QC thresholds remain unchanged; no candidate becomes the submission primary automatically.

Audit all 29 D52 material/appearance inputs against their actual extraction code. BSE bright summaries depend on the bright threshold; pore/crack summaries depend on the pore threshold. Three Inlens particle summaries use eroded bright interiors. ETD particle/graphite ridge fractions also use a dominant orientation estimated from joint bright/graphite interiors. `ridge_p97` and `inlens_grad_energy` use those joint interiors directly. The latter is not a whole-frame gradient. BSE correlation length and FFT slope are sampled raw-image appearance features, with acquisition sensitivity but no phase-mask dependency.

Prespecify four procedures, with no selection using drop labels:

1. **legacy_matched**: unchanged 29 numerical inputs, refitted with the audit's shared folds. The separately saved frozen v2 evaluation is reported as the historical benchmark.
2. **direct_mask_gate**: sensitivity only. Mark eight bright geometry inputs, the ETD particle ridge input and three Inlens particle summaries missing when bright quality is bad/unknown. Mark eight pore/crack inputs missing when pore quality is bad/unknown. Retain the seven indirect/joint-interior inputs to expose the cost of incomplete dependency handling.
3. **dependency_gate**: primary audit candidate. Apply the bright-only/pore-only rules plus invalidate all eight joint-mask inputs when either relevant mask is bad/unknown, including ETD particle ridge coverage. This is a conservative dependency policy, not independently validated segmentation repair.
4. **quality_flags_only**: acquisition-shortcut comparator with only the two bad-or-unknown quality indicators. Never use it for the submission bet.

Bright quality uses the existing data-derived `bright_low_contrast` boolean; missing flags are unknown, not good. Pore quality uses the existing fixed raised-black-level rule `bse_p1 > 10`, re-derived without known site IDs or batch labels. Missing/invalid black-level values are unknown. On these known tables the data rule must agree with the existing grey-pore flags; `pore_mode_resolved` is not a quality selector because it is false on every known site. Contrast stretching alone is reported but does not invalidate all shape measurements by a new unvalidated rule. Cracked reference sites remain included. All original measurements are preserved separately.

Invalid/unknown-dependent measurements become NaN in the candidate model matrix, never a numeric zero or a predictor flag. Existing nonfinite measurements remain unavailable. Use training-fold median imputation without missingness indicators, fold-local scaling, balanced L1 logistic regression, C grid 0.1/0.5/2, seed 0, three inner stratified folds and leave-one-site-out on all 31 known sites (7/7/17). Keep empty training features as zero constants, disclose training availability, and do not interpret imputed values as observations. Quality patterns can still be indirectly identifiable after median imputation; the flag-only control and subgroup errors qualify that risk.

Use one shared content-based row order from the two mask-independent BSE summaries, without site-name or batch-label influence. Their known-site pairs must be unique. This fixes the same inner-fold allocation across the four procedures and stops rejected raw values changing the ordering. Reordered site names and rows must preserve results. The audit's matched legacy can differ from frozen v2 because inner folds differ; report both rather than attributing all movement to quality handling.

Save known-site OOF scores, confusion counts, recall, balanced accuracy, Brier score and reliability counts. Run 200 shared seed-0 site-label permutations, refitting the complete nested procedure per permutation. The dependency candidate is the sole primary test; direct and flag-only results are diagnostic, not selectable winners. Save the paired candidate-minus-legacy balanced-accuracy difference and its corresponding permutation diagnostic. Site-resampling intervals of paired OOF decisions are descriptive conditional sensitivity because CV fits overlap and specimen independence is unresolved. No binomial generalisation/calibration guarantee.

Before reading the drop features in this audit, complete and save known-only evaluation and candidate full fits with source/data/protocol hashes. Only then apply all prespecified policies to the three already labelled failure examples. Show changed scores, input coverage, exact assigned-minus-runner logits, quality reasons and model contributions; do not use their labels for C selection, normalisation, variant choice or deployment. Any post-feedback accuracy is development-only.

Mandatory safety checks: metadata/site/batch names cannot enter numerical material inputs; bad-value perturbations leave dependency-gated fits/scores invariant; missing/false/string flags are handled explicitly; pore and bright failures propagate through cross-detector dependencies; imputation is fitted without held-out rows; NaNs/all-empty features keep declared feature positions; no overwrite of evidence; preserved artifacts retain their hashes. Independent mask/component review and specimen/session metadata remain open.

Deliver a dependency catalogue, coverage/influence tables, known-site comparison, failure-example diagnostics and an illustrated report. Completion requires a recommendation supported by these results, not correcting all three failure examples. No raw TIFFs, automatic KPI trust promotion, organiser message or Git commit is part of this audit.
